# 怎样读懂一篇论文

<div class="lesson-lead">读论文不是从第一行读到最后一行，更不是每个公式都推完才算懂。目标是用有限时间回答一组越来越深入的问题。</div>

## 先接受一个事实：论文不是教材

论文的任务是向同行说明一个新贡献，通常默认读者已经懂背景。它会压缩解释、突出最好结果，并把大量实现细节移到附录或省略。看不懂不等于你不适合，往往只是缺了一层脚手架。

## 第一遍：15 分钟，只找地图

按这个顺序：标题 → 摘要 → Introduction 最后一段 → 主架构图 → 结果主表 → Conclusion。

只写下五句话：

1. 它想解决什么瓶颈？
2. 旧方法为什么不够？
3. 它最关键的一处变化是什么？
4. 主要收益用什么指标衡量？
5. 你现在最不懂的三个词是什么？

第一遍不要在公式处停留。你是在决定这篇论文值不值得继续读。

## 第二遍：沿数据流追机制

把方法画成方框箭头，并在每条边写张量形状。固定问：

- 输入和输出分别是什么？
- 训练时保存什么？推理时保存什么？
- 哪个量随序列长度、专家数或层数增长？
- 与最近的 baseline 相比，到底只改了哪里？
- 极限情况下会退化成什么？

例如读 MLA，不要只抄“低秩压缩”。你应能说出：标准 MHA 为每层每个历史 token 保存所有 head 的 K/V；MLA 保存低维 latent 表示，使用时再投影，因此重点节省 KV Cache。

## 第三遍：审证据

看实验时把结论分三层：

<div class="evidence-legend">
  <div><strong>[论文明示]</strong><br>原文、公式、配置或表格直接支持</div>
  <div><strong>[相关工作]</strong><br>需要另一篇论文补足背景</div>
  <div><strong>[解释 / 推论]</strong><br>合理的教学或工程解释，但不是独立证据</div>
</div>

然后检查：

- Baseline 是否在同样数据、算力和评测设置下？
- 是否有只改变一个变量的消融实验？
- 报告的是单点最好结果，还是成本—能力曲线？
- 误差条、运行次数、失败率是否披露？
- 哪些复现关键项没有公开？

## 一页论文笔记模板

```text
论文：
一句话贡献：

1. 解决的瓶颈：质量 / FLOPs / 显存 / 通信 / 数据 / 奖励 / 延迟
2. 输入 → 核心变化 → 输出：
3. 训练状态与推理状态：
4. 复杂度如何随 T、d、E、k 变化：
5. 最关键的消融：
6. 论文没有披露什么：
7. 它在 K3 技术链上的位置：
8. 我仍然不懂的问题：
```

## 一个常见陷阱：“更高效”到底省了什么

看到高效、低成本、scalable，立刻追问：

| 可能省下的资源 | 常用证据 |
|---|---|
| 训练 FLOPs | 固定 token 数的计算量、吞吐 |
| 推理 FLOPs | 每 token 运算量 |
| 显存 | 参数、优化器、激活、KV Cache 分项 |
| 通信 | All-to-All / AllReduce 字节量 |
| 延迟 | TTFT、TPOT、端到端 latency |
| 总成本 | 固定质量下的 GPU 时或价格 |

一个方法可能节省 KV Cache，却增加投影计算；可能减少 FLOPs，却因不规则访存而没有更低延迟。不要把它们混成一个“效率”。
