# 先从这里开始

<div class="lesson-lead">这一页不考你。它只做一件事：告诉你接下来会遇到什么、为什么要按这个顺序学，以及“学会”到底是什么样。</div>

## 你不需要先会什么

你不需要学过高等数学，不需要训练过神经网络，也不需要先读完 Transformer 论文。能看懂简单的加减乘除、愿意在遇到陌生词时停下来画个图，就足够开始。

教程把知识分成三层：

| 层次 | 你要获得的能力 | 例子 |
|---|---|---|
| 直觉 | 能用自己的话讲清问题 | “KV Cache 像把查过的资料做成便签，避免每次重查” |
| 机制 | 能沿着数据流说出每一步 | token → 向量 → attention → logits → 下一个 token |
| 数学 | 能看懂公式里的对象与变化方向 | 上下文变长一倍，标准 KV Cache 大约也变成两倍 |

一开始不要追求推导所有公式。先能回答“输入是什么、输出是什么、它解决了什么问题”。

## 用一个句子认识语言模型

假设输入：

> 今天天气很好，我们去公园放____

模型不会直接“理解空格”。它依次做五件事：

1. **切成 token**：把文本拆成模型词表认识的片段；
2. **变成向量**：每个 token 查表得到一串数字；
3. **交换信息**：attention 让当前位置读取前文；
4. **层层变换**：多个模块不断加工表示；
5. **给出概率**：对词表里每个候选 token 打分，也许“风筝”最高。

生成完“风筝”，模型把它拼回前文，再预测下一个 token。重复许多次，就形成了我们看到的一段回答。

::: tip 第一条主线
语言模型的核心训练任务不是“回答问题”，而是“根据前文预测下一个 token”。问答、代码、推理和工具调用能力，是在这个基础上继续训练出来的。
:::

## Kimi K3 为什么值得当作学习地图

K3 不只是一个模型结构。它把现代大模型最重要的几类问题放在了一起：

| 当规模变大 | 老办法遇到的麻烦 | 课程中的关键词 |
|---|---|---|
| 上下文变长 | Attention 计算、缓存越来越大 | KDA、MLA、KV Cache |
| 网络变深 | 早期信息在残差流里被稀释 | Attention Residuals |
| 参数变多 | 每个 token 都跑全部参数太贵 | MoE、LatentMoE |
| 推理变长 | 奖励稀疏、轨迹很贵、环境会变化 | RL、partial rollout、Agent |
| 请求跨度变大 | 短请求与百万 token 请求互相拖累 | prefix cache、调度、在线服务 |

所以我们不把 K3 当成一堆要背的模块名，而把它当成一张“问题 → 方案 → 代价”的地图。

## 推荐学习顺序

### 第 0 站：补齐最小前置知识

- [数学热身](/start/math)：向量、矩阵、概率和函数，只学后面马上会用到的部分；
- [Transformer 第一课](/start/transformer)：走完一个 token 的完整旅程；
- [论文阅读法](/start/paper-reading)：学会区分论文说了什么、你推断了什么。

### 第 1 站：建立语言模型全景

学习第 0–2 章。你会理解自回归生成、Prefill、Decode 和 KV Cache。学完后应该能解释为什么“训练快”不代表“生成也快”。

### 第 2 站：拆开 K3 的三维信息流

学习第 3–9 章：

- 序列维：KDA + MLA；
- 深度维：Attention Residuals；
- 通道维：Stable LatentMoE。

### 第 3 站：理解能力怎样产生

学习第 10–12 章。重点不是背 PPO、GRPO 等算法缩写，而是理解 pre-training、SFT、RL、蒸馏分别改变什么。

### 第 4 站：把模型放进真实系统

学习第 13–16 章。你会看到并行训练、在线服务、Agent 环境和论文评测为什么必须一起考虑。

## 三个自学规则

### 规则一：任何缩写都展开成一句话

看到 `MoE`，不要只记 “Mixture of Experts”。要说：

> 模型拥有许多 FFN 专家，但 router 为每个 token 只挑少量专家执行，从而让总参数容量增长得比单 token 计算更快。

一句话说不清，说明还没形成心智模型。

### 规则二：每个方案都记三本账

学习任何效率技术时，分别问：

1. **计算账**：做了多少乘加？
2. **内存账**：需要存参数、激活还是缓存？
3. **通信账**：不同 GPU 之间要搬什么？

很多“更高效”只优化其中一本账，却让另一本账更贵。

### 规则三：先做极限情况

如果公式里有一个门控系数 `β`：

- `β = 0` 会怎样？
- `β = 1` 会怎样？
- 输入重复 100 次会怎样？

极限情况通常比直接背公式更快暴露机制。
